Modulo 1 Fundamentos de la Ley 21.719 y Arquitectura Snowflake Arts. 1-3

Que es la Ley 21.719?

La Ley 21.719 de 13 de diciembre de 2024 reforma sustancialmente la Ley 19.628 sobre Proteccion de la Vida Privada, modernizando el marco chileno de proteccion de datos personales. Crea la Agencia de Proteccion de Datos Personales como organo autonomo fiscalizador y establece un regimen sancionatorio con multas de hasta 20.000 UTM para infracciones gravisimas. Entra en vigencia el 1 de diciembre de 2026.

Conceptos fundamentales (Art. 2)

Principios del Tratamiento (Art. 3)

La Ley 21.719 establece 7 principios rectores que se implementan en Snowflake:

#PrincipioImplementacion Snowflake
1Licitud — toda base legal documentadaTag LEY21719_BASE_LEGAL
2Finalidad — proposito especifico y legitimoTag LEY21719_FINALIDAD + Row Access Policy
3Proporcionalidad — datos minimos necesariosProjection Policies + Masking Policies
4Calidad — datos exactos y actualizadosProcedimiento ARCO_CORRECTION
5Seguridad — medidas tecnicas adecuadasRBAC, Encryption, Masking, RAP
6Responsabilidad — demostrar cumplimientoACCESS_HISTORY, Governance Dashboard
7Informacion y transparenciaTags de metadatos en todas las tablas

Modulo 2 Infraestructura de Gobernanza y RBAC Arts. 14 quater, 14 sexies

Modulo 4 Tags Personalizados para Ley 21.719 Arts. 3, 12-13

Ademas de los tags de sistema (clasificacion automatica), creamos tags personalizados para documentar metadatos exigidos por la Ley 21.719: base legal, finalidad, periodo de retencion, y responsables.

1 Crear Tags Ley 21.719

USE ROLE LEY21719_DATA_STEWARD;
USE SCHEMA LEY21719_GOVERNANCE.TAGS;

CREATE OR REPLACE TAG LEY21719_DATA_CATEGORY
  ALLOWED_VALUES
    'DATO_PERSONAL',
    'DATO_PERSONAL_SENSIBLE',
    'DATO_ANONIMIZADO',
    'NO_PERSONAL'
  COMMENT = 'Clasificacion del dato conforme Art. 2 de la Ley 21.719';

    'EJECUCION_CONTRATO',
    'OBLIGACION_LEGAL',
    'INTERES_VITAL',
    'INTERES_PUBLICO',
    'INTERES_LEGITIMO'
  COMMENT = 'Base legal para tratamiento conforme Arts. 12-13 de la Ley 21.719';

CREATE OR REPLACE TAG LEY21719_FINALIDAD
  COMMENT = 'Descripcion de la finalidad del tratamiento (Art. 3)';

CREATE OR REPLACE TAG LEY21719_RETENCION

Herencia de Tags y Tag-Based Masking Los tags de metadatos (BASE_LEGAL, FINALIDAD, RETENCION, RESPONSABLE) se aplican a la tabla y son heredados por todas las columnas. El tag LEY21719_DATA_CATEGORY se aplica individualmente por columna para evitar que columnas no-PII (como DEPARTAMENTO, COMUNA, REGION) sean enmascaradas por el tag-based masking del Modulo 5. Las columnas sensibles (GENERO, ETNIA) reciben DATO_PERSONAL_SENSIBLE.

Modulo 5 Politicas de Enmascaramiento Dinamico Arts. 14 bis, 3

Las masking policies protegen datos personales en tiempo de consulta. El dato original permanece intacto en la tabla, pero usuarios no autorizados ven valores enmascarados.

1 Crear Masking Policies por Tipo de Dato

Enmascaramiento de RUT 
USE ROLE LEY21719_PRIVACY_ADMIN;

CREATE OR REPLACE MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_RUT
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY21719_DELEGADO_DATOS') THEN val
    WHEN IS_ROLE_IN_SESSION('LEY21719_PRIVACY_ADMIN') THEN val
    ELSE CONCAT(
      LEFT(val, 3),
      '***.',
      '***-*'
    )
  END
  COMMENT = 'Enmascara RUT para roles no autorizados (Art. 14 bis Ley 21.719)';
Enmascaramiento de Email 
CREATE OR REPLACE MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_EMAIL
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY21719_DELEGADO_DATOS') THEN val
    WHEN IS_ROLE_IN_SESSION('LEY21719_PRIVACY_ADMIN') THEN val
    ELSE REGEXP_REPLACE(val, '.+\\@', '*****@')
  END
  COMMENT = 'Enmascara parte local del email (Art. 14 bis Ley 21.719)';
Enmascaramiento de Telefono 
CREATE OR REPLACE MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_PHONE
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY21719_DELEGADO_DATOS') THEN val
    ELSE CONCAT('+56 9 **** ', RIGHT(val, 4))
  END
  COMMENT = 'Enmascara telefono conservando ultimos 4 digitos';
Enmascaramiento Generico (String, Number, Date) 
CREATE OR REPLACE MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_PII_STRING
  AS (val STRING) RETURNS STRING ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY21719_DELEGADO_DATOS') THEN val
    WHEN IS_ROLE_IN_SESSION('LEY21719_PRIVACY_ADMIN') THEN val
    ELSE '***PROTEGIDO***'
  END;

CREATE OR REPLACE MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_PII_NUMBER
  AS (val NUMBER) RETURNS NUMBER ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY21719_DELEGADO_DATOS') THEN val
    ELSE NULL
  END;

CREATE OR REPLACE MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_PII_DATE
  AS (val DATE) RETURNS DATE ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY21719_DELEGADO_DATOS') THEN val
    ELSE DATE_FROM_PARTS(1900, 01, 01)
  END;

2 Aplicar Policies Directamente en las Columnas

ALTER TABLE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES MODIFY COLUMN
  RUT SET MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_RUT;

ALTER TABLE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES MODIFY COLUMN
  EMAIL SET MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_EMAIL;

ALTER TABLE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES MODIFY COLUMN
  TELEFONO SET MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_PHONE;

ALTER TABLE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES MODIFY COLUMN
  FECHA_NACIMIENTO SET MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_PII_DATE;

3 Tag-Based Masking (Enfoque Escalable)

USE ROLE LEY21719_PRIVACY_ADMIN;

ALTER TAG LEY21719_GOVERNANCE.TAGS.LEY21719_DATA_CATEGORY SET
  MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_PII_STRING,
  MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_PII_NUMBER,
  MASKING POLICY LEY21719_GOVERNANCE.POLICIES.MASK_PII_DATE;
Precedencia de Policies Cuando una columna tiene ambas una masking policy directa y una tag-based masking policy, la policy directa tiene precedencia. Esto permite crear una proteccion generica via tags y refinamientos especificos por columna.

Modulo 6 Row Access Policies Art. 3 (finalidad), Art. 14 bis

Las Row Access Policies restringen cuales filas un usuario puede ver, implementando el principio de finalidad (Art. 3) — cada departamento solo accede a los datos necesarios para su proposito.

1 Crear Tabla de Mapeo y Row Access Policy

USE ROLE LEY21719_PRIVACY_ADMIN;

CREATE OR REPLACE TABLE LEY21719_GOVERNANCE.POLICIES.ACCESS_MAPPING (
  ROLE_NAME       STRING, DEPARTMENT STRING, ALLOWED_PURPOSE STRING, REGION STRING
);

INSERT INTO LEY21719_GOVERNANCE.POLICIES.ACCESS_MAPPING VALUES
  ('RRHH_ANALYST',             'RRHH',      'GESTION_PERSONAL',  'CHILE'),
  ('MARKETING_ANALYST',        'MARKETING', 'CAMPANAS',          'CHILE'),
  ('FINANZAS_ANALYST',         'FINANZAS',  'FACTURACION',       'CHILE'),
  ('LEY21719_DELEGADO_DATOS',  'ALL',       'GOBERNANZA',        'ALL'),
  ('LEY21719_PRIVACY_ADMIN',   'ALL',       'GOBERNANZA',        'ALL');

CREATE OR REPLACE ROW ACCESS POLICY
  LEY21719_GOVERNANCE.POLICIES.RAP_PURPOSE_LIMITATION
  AS (department STRING) RETURNS BOOLEAN ->
  IS_ROLE_IN_SESSION('LEY21719_DELEGADO_DATOS')
  OR IS_ROLE_IN_SESSION('LEY21719_PRIVACY_ADMIN')
  OR EXISTS (
    SELECT 1
    FROM LEY21719_GOVERNANCE.POLICIES.ACCESS_MAPPING am
    WHERE am.ROLE_NAME = CURRENT_ROLE()
      AND (am.DEPARTMENT = department OR am.DEPARTMENT = 'ALL')
  )
  COMMENT = 'Limita acceso por departamento conforme principio de finalidad (Art. 3 Ley 21.719)';

ALTER TABLE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES
  ADD ROW ACCESS POLICY LEY21719_GOVERNANCE.POLICIES.RAP_PURPOSE_LIMITATION
  ON (DEPARTAMENTO);

Orden de Evaluacion Snowflake evalua primero la Row Access Policy (filtrado de filas), luego las Projection Policies (bloqueo de columnas en el output), y por ultimo aplica las Masking Policies (enmascaramiento de valores). Esto significa que un RRHH_ANALYST vera solo 2 filas, y en esas filas los datos personales estaran enmascarados.

Modulo 7 Politicas de Proyeccion (Projection Policies) Art. 3 (proporcionalidad), Art. 16

Las Projection Policies son la tercera capa de defensa. Mientras las masking policies transforman valores y las Row Access Policies filtran filas, las projection policies impiden que una columna aparezca en el resultado final — implementando el principio de proporcionalidad (Art. 3) de la Ley 21.719.

AspectoRow Access PolicyProjection PolicyMasking Policy
Que controlaCuales FILAS el usuario veCuales COLUMNAS aparecen en el resultadoComo los VALORES aparecen
EnforcementFiltra silenciosamenteFAIL (bloquea query) o NULLIFY (retorna NULL)Transforma el valor
Articulos Ley 21.719Art. 3 (Finalidad)Art. 3 (Proporcionalidad) / Art. 16 (Sensibles)Art. 14 bis (Seguridad)
Defensa en Profundidad — Orden de Evaluacion en Snowflake
Capa 1: Row Access Policy → filtra FILAS (quien ve cuales registros)
Capa 2: Projection Policy → bloquea COLUMNAS en el output (quien ve cuales campos)
Capa 3: Masking Policy → transforma VALORES visibles (como aparecen los datos)

En la tabla CLIENTES, las tres capas estan activas simultaneamente.

1 Crear y Aplicar Projection Policies

USE ROLE LEY21719_PRIVACY_ADMIN;

-- FAIL para datos sensibles (GENERO, ETNIA)
CREATE OR REPLACE PROJECTION POLICY LEY21719_GOVERNANCE.POLICIES.PROJ_SENSITIVE_BLOCK
  AS () RETURNS PROJECTION_CONSTRAINT ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY21719_DELEGADO_DATOS')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    WHEN IS_ROLE_IN_SESSION('LEY21719_PRIVACY_ADMIN')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    ELSE PROJECTION_CONSTRAINT(ALLOW => false)
  END
  COMMENT = 'Bloquea proyeccion de datos sensibles (Art. 16 Ley 21.719)';

-- NULLIFY para PII general (DIRECCION)
CREATE OR REPLACE PROJECTION POLICY LEY21719_GOVERNANCE.POLICIES.PROJ_PII_NULLIFY
  AS () RETURNS PROJECTION_CONSTRAINT ->
  CASE
    WHEN IS_ROLE_IN_SESSION('LEY21719_DELEGADO_DATOS')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    WHEN IS_ROLE_IN_SESSION('LEY21719_PRIVACY_ADMIN')
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    ELSE PROJECTION_CONSTRAINT(ALLOW => false, ENFORCEMENT => 'NULLIFY')
  END
  COMMENT = 'Retorna NULL para columnas PII no autorizadas (Art. 3 Ley 21.719)';

ALTER TABLE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES MODIFY COLUMN
  GENERO SET PROJECTION POLICY LEY21719_GOVERNANCE.POLICIES.PROJ_SENSITIVE_BLOCK;
ALTER TABLE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES MODIFY COLUMN
  ETNIA SET PROJECTION POLICY LEY21719_GOVERNANCE.POLICIES.PROJ_SENSITIVE_BLOCK;
ALTER TABLE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES MODIFY COLUMN
  DIRECCION SET PROJECTION POLICY LEY21719_GOVERNANCE.POLICIES.PROJ_PII_NULLIFY;

Modulo 8 Derechos del Titular (ARCO-P) Arts. 4-8, 10

Los Arts. 4-8 de la Ley 21.719 garantizan al titular derechos ampliados sobre sus datos, conocidos como derechos ARCO-P (Acceso, Rectificacion, Cancelacion/Supresion, Oposicion, Portabilidad). Implementamos cada derecho como un stored procedure con auditoria automatica.

DerechoArticuloDescripcionProcedure
AccesoArt. 4Confirmar existencia y obtener acceso a los datosARCO_ACCESS
RectificacionArt. 5Corregir datos inexactos o desactualizadosARCO_CORRECTION
SupresionArt. 6Eliminar o anonimizar datos innecesariosARCO_DELETE
OposicionArt. 7Oponerse al tratamiento en ciertas circunstanciasProceso organizacional
PortabilidadArt. 8Exportar datos en formato estructuradoARCO_PORTABILITY

1 Crear Tabla de Auditoria ARCO-P

USE ROLE LEY21719_DELEGADO_DATOS;

CREATE OR REPLACE TABLE LEY21719_GOVERNANCE.AUDIT.ARCO_LOG (
  REQUEST_ID    STRING DEFAULT UUID_STRING(),
  REQUEST_TYPE  STRING,
  TITULAR_ID    STRING    COMMENT 'RUT o identificador del titular',
  REQUESTED_BY  STRING DEFAULT CURRENT_USER(),
  REQUESTED_AT  TIMESTAMP_LTZ DEFAULT CURRENT_TIMESTAMP(),
  STATUS        STRING DEFAULT 'PENDIENTE',
  COMPLETED_AT  TIMESTAMP_LTZ,
  DETAILS       VARIANT
)
COMMENT = 'Log de solicitudes de derechos del titular (Arts. 4-8 Ley 21.719)';

2 Derecho de Acceso (Art. 4)

CREATE OR REPLACE PROCEDURE LEY21719_GOVERNANCE.AUDIT.ARCO_ACCESS(
  TITULAR_RUT STRING
)
RETURNS TABLE()
LANGUAGE SQL
AS
$$
BEGIN
  INSERT INTO LEY21719_GOVERNANCE.AUDIT.ARCO_LOG
    (REQUEST_TYPE, TITULAR_ID, STATUS, COMPLETED_AT)
  VALUES ('ACCESO', :TITULAR_RUT, 'CONCLUIDO', CURRENT_TIMESTAMP());

  LET rs RESULTSET := (
    SELECT ID, NOMBRE, RUT, EMAIL, TELEFONO, FECHA_NACIMIENTO,
           DIRECCION, COMUNA, REGION, FECHA_REGISTRO
    FROM EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES
    WHERE RUT = :TITULAR_RUT
  );
  RETURN TABLE(rs);
END;
$$;

3 Derecho de Rectificacion (Art. 5)

CREATE OR REPLACE PROCEDURE LEY21719_GOVERNANCE.AUDIT.ARCO_CORRECTION(
  TITULAR_RUT STRING, CAMPO STRING, NUEVO_VALOR STRING
)
RETURNS STRING
LANGUAGE SQL
AS
$$
BEGIN
  INSERT INTO LEY21719_GOVERNANCE.AUDIT.ARCO_LOG
    (REQUEST_TYPE, TITULAR_ID, DETAILS)
  SELECT 'RECTIFICACION', :TITULAR_RUT,
     OBJECT_CONSTRUCT('campo', :CAMPO, 'nuevo_valor', :NUEVO_VALOR);

  IF (:CAMPO = 'EMAIL') THEN
    UPDATE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES
    SET EMAIL = :NUEVO_VALOR WHERE RUT = :TITULAR_RUT;
  ELSEIF (:CAMPO = 'TELEFONO') THEN
    UPDATE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES
    SET TELEFONO = :NUEVO_VALOR WHERE RUT = :TITULAR_RUT;
  ELSEIF (:CAMPO = 'DIRECCION') THEN
    UPDATE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES
    SET DIRECCION = :NUEVO_VALOR WHERE RUT = :TITULAR_RUT;
  ELSE
    RETURN 'Error: Campo no permitido para rectificacion via ARCO-P.';
  END IF;

  UPDATE LEY21719_GOVERNANCE.AUDIT.ARCO_LOG
  SET STATUS = 'CONCLUIDO', COMPLETED_AT = CURRENT_TIMESTAMP()
  WHERE TITULAR_ID = :TITULAR_RUT AND REQUEST_TYPE = 'RECTIFICACION' AND STATUS = 'PENDIENTE';

  RETURN CONCAT('Campo ', :CAMPO, ' rectificado con exito para el titular ', :TITULAR_RUT);
END;
$$;

4 Derecho de Supresion / Anonimizacion (Art. 6)

CREATE OR REPLACE PROCEDURE LEY21719_GOVERNANCE.AUDIT.ARCO_DELETE(
  TITULAR_RUT STRING
)
RETURNS STRING
LANGUAGE SQL
AS
$$
BEGIN
  LET cnt NUMBER := (
    SELECT COUNT(*) FROM EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES WHERE RUT = :TITULAR_RUT
  );
  IF (:cnt = 0) THEN RETURN 'Error: Titular no encontrado.'; END IF;

  UPDATE EMPRESA_DEMO_CL.DATOS_CLIENTES.CLIENTES
  SET NOMBRE = 'ANONIMIZADO', RUT = 'XX.XXX.XXX-X',
      EMAIL = CONCAT('anonimizado_', ID, '@removed.ley21719'),
      TELEFONO = '+56 9 0000 0000', FECHA_NACIMIENTO = DATE_FROM_PARTS(1900,01,01),
      DIRECCION = 'ELIMINADO', COMUNA = 'ELIMINADO', REGION = 'XX',
      GENERO = NULL, ETNIA = NULL
  WHERE RUT = :TITULAR_RUT;

  INSERT INTO LEY21719_GOVERNANCE.AUDIT.ARCO_LOG
    (REQUEST_TYPE, TITULAR_ID, STATUS, COMPLETED_AT)
  VALUES ('SUPRESION', :TITULAR_RUT, 'CONCLUIDO', CURRENT_TIMESTAMP());

  RETURN CONCAT('Datos del titular ', :TITULAR_RUT, ' anonimizados con exito.');
END;
$$;

5 Derecho de Portabilidad (Art. 8)

CREATE STAGE IF NOT EXISTS EMPRESA_DEMO_CL.DATOS_CLIENTES.ARCO_EXPORT
  COMMENT = 'Stage para exportacion de datos en solicitudes de portabilidad';

CREATE OR REPLACE PROCEDURE LEY21719_GOVERNANCE.AUDIT.ARCO_PORTABILITY(
  TITULAR_RUT STRING
)
RETURNS STRING
LANGUAGE SQL
AS
$$
BEGIN
  COPY INTO @EMPRESA_DEMO_CL.DATOS_CLIENTES.ARCO_EXPORT/portabilidad/
  FROM (
    SELECT ID, NOMBRE, RUT, EMAIL, TELEFONO, FECHA_NACIMIENTO,

    (REQUEST_TYPE, TITULAR_ID, STATUS, COMPLETED_AT)
  VALUES ('PORTABILIDAD', :TITULAR_RUT, 'CONCLUIDO', CURRENT_TIMESTAMP());

  RETURN CONCAT('Datos exportados a @ARCO_EXPORT/portabilidad/ para el titular ', :TITULAR_RUT);
END;
$$;

Modulo 9 Monitoreo, Auditoria y Cumplimiento Arts. 14 bis-ter, 34 bis-quater

El monitoreo continuo es esencial para demostrar cumplimiento con la Ley 21.719. Este modulo cubre auditoria de acceso, reportes de cobertura, y alertas para vulneraciones de seguridad (Art. 14 ter).

1 Auditoria de Acceso a Datos Personales

USE ROLE ACCOUNTADMIN;

SELECT
  ah.USER_NAME, qh.ROLE_NAME, ah.QUERY_START_TIME,
  boa.VALUE:objectName::STRING AS OBJECT_ACCESSED,
  boa.VALUE:objectDomain::STRING AS OBJECT_TYPE, ah.QUERY_ID
FROM SNOWFLAKE.ACCOUNT_USAGE.ACCESS_HISTORY ah
  JOIN SNOWFLAKE.ACCOUNT_USAGE.QUERY_HISTORY qh ON ah.QUERY_ID = qh.QUERY_ID
  ,LATERAL FLATTEN(input => ah.BASE_OBJECTS_ACCESSED) boa
WHERE ah.QUERY_START_TIME >= DATEADD('day', -30, CURRENT_TIMESTAMP())
  AND boa.VALUE:objectName::STRING ILIKE '%CLIENTES%'
ORDER BY ah.QUERY_START_TIME DESC LIMIT 100;

2 Reporte de Cobertura de Tags Ley 21.719

SELECT
  t.TABLE_CATALOG AS DATABASE_NAME, t.TABLE_SCHEMA AS SCHEMA_NAME,
  t.TABLE_NAME, t.ROW_COUNT,
  COALESCE(tr.TAG_VALUE, '*** SIN TAG ***') AS LEY21719_CATEGORY,
  CASE WHEN tr.TAG_VALUE IS NOT NULL THEN 'CONFORME' ELSE 'PENDIENTE'
  END AS STATUS_CUMPLIMIENTO
FROM SNOWFLAKE.ACCOUNT_USAGE.TABLES t
LEFT JOIN SNOWFLAKE.ACCOUNT_USAGE.TAG_REFERENCES tr
  ON t.TABLE_CATALOG = tr.OBJECT_DATABASE AND t.TABLE_SCHEMA = tr.OBJECT_SCHEMA
  AND t.TABLE_NAME = tr.OBJECT_NAME AND tr.TAG_NAME = 'LEY21719_DATA_CATEGORY' AND tr.DOMAIN = 'TABLE'
WHERE t.DELETED IS NULL AND t.TABLE_SCHEMA != 'INFORMATION_SCHEMA'
ORDER BY STATUS_CUMPLIMIENTO DESC;

3 Monitorear Solicitudes ARCO-P Pendientes (SLA: 30 dias habiles)

USE ROLE LEY21719_DELEGADO_DATOS;

SELECT REQUEST_ID, REQUEST_TYPE, TITULAR_ID, REQUESTED_AT, STATUS,
  DATEDIFF('day', REQUESTED_AT, CURRENT_TIMESTAMP()) AS DIAS_ABIERTO,
  CASE
    WHEN DATEDIFF('day', REQUESTED_AT, CURRENT_TIMESTAMP()) > 30 THEN 'ATRASADO'
    WHEN DATEDIFF('day', REQUESTED_AT, CURRENT_TIMESTAMP()) > 20 THEN 'ATENCION'
    ELSE 'DENTRO DEL PLAZO'
  END AS SLA_STATUS
FROM LEY21719_GOVERNANCE.AUDIT.ARCO_LOG
WHERE STATUS = 'PENDIENTE'
ORDER BY REQUESTED_AT ASC;

4 Alerta para Acceso Masivo a Datos Personales

USE ROLE ACCOUNTADMIN;
CREATE OR REPLACE NOTIFICATION INTEGRATION LEY21719_NOTIFICATIONS
  TYPE = EMAIL ENABLED = TRUE
  ALLOWED_RECIPIENTS = ($LEY21719_DPO_EMAIL);

USE ROLE LEY21719_DELEGADO_DATOS;

CREATE OR REPLACE ALERT LEY21719_GOVERNANCE.AUDIT.ALERT_MASS_DATA_ACCESS
  WAREHOUSE = LEY21719_TRAINING_WH
  SCHEDULE = 'USING CRON 0 */6 * * * America/Santiago'
  IF (EXISTS (
    SELECT 1 FROM SNOWFLAKE.ACCOUNT_USAGE.QUERY_HISTORY
    WHERE EXECUTION_STATUS = 'SUCCESS' AND ROWS_PRODUCED > 10000
      AND QUERY_START_TIME >= DATEADD('hour', -6, CURRENT_TIMESTAMP())
      AND (QUERY_TEXT ILIKE '%clientes%' OR QUERY_TEXT ILIKE '%datos_personales%')
  ))
  THEN
    CALL SYSTEM$SEND_EMAIL(
      'LEY21719_NOTIFICATIONS', $LEY21719_DPO_EMAIL,
      'ALERTA LEY 21.719: Acceso masivo a datos personales detectado',
      'Una consulta retorno mas de 10,000 registros de tablas con datos personales en las ultimas 6 horas. Verifique el ACCESS_HISTORY para detalles.'
    );

ALTER ALERT LEY21719_GOVERNANCE.AUDIT.ALERT_MASS_DATA_ACCESS RESUME;
